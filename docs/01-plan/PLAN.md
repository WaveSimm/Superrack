# PLAN — ASIO 다채널 VST3 인서트 프로세서 (Superrack)

> PDCA: Plan · Level: Enterprise-rigor(웹 인프라 도구 제외) · 개정일: 2026-06-29
> 상위 설계: [`../02-design/DESIGN.md`](../02-design/DESIGN.md) · 원본 [`../../asio-vst3-host-design.md`](../../asio-vst3-host-design.md)

## 1. 한 줄 정의
ASIO 입력 채널(시작 2 → 최대 32)마다 독립 VST3 체인을 적용해 같은 번호의 출력 채널로 **1:1 송출**(라이브 모니터/리턴)하고, **동시에 채널별 Dry(원음)만 멀티트랙 녹음**하는 Windows 네이티브 GUI 프로그램.

## 2. 목표 / 비목표
**목표**
- 채널별 독립 VST3 인서트 체인 (합산·믹스 버스 없음)
- 입력 i → 체인 → 출력 i 1:1 라우팅, 저지연 라이브 모니터
- 채널별 Dry 멀티트랙 녹음(32-bit float WAV, 채널당 1파일), 샘플 정확 동기화
- 2채널로 완성 후 최대 32채널 확장

**비목표**
- 믹스 버스/마스터/페이더/팬, Wet 녹음, 채널 간 합산
- 크로스플랫폼(ASIO는 Windows 전용), 웹/백엔드/DB

## 3. 핵심 제약 (요구사항 소스)
1. ASIO 단일 디바이스 독점 (입출력 동일 드라이버), 입력 채널 수 ≤ 출력 채널 수
2. 샘플레이트·버퍼는 드라이버 결정 (32채널 시 128~256 권장)
3. 오디오 콜백 스레드 금지: 할당·락·파일 I/O·로깅·예외
4. 단일 오디오 스레드 — 32채널 × 체인은 CPU 1순위 리스크 → **해소(2026-07-03)**: A2 채널 병렬 워커 풀(실측 3.0×) + A3 스톨 해결. DESIGN §5.8, `measurements/cpu-profile-parallel-2026-07-03.md`

## 4. 확정 결정 (2026-06-29)
| # | 항목 | 확정 |
|---|------|------|
| 1 | 형태 | GUI 앱 (채널 뷰 + 플러그인 네이티브 에디터 창) |
| 2 | 채널 구조 | 채널별 독립 VST3 체인, 2ch → 32ch |
| 3 | 라우팅 | 1:1, 합산·페이더·팬·마스터 없음 |
| 4 | 엔진 | 수동 채널별 처리 (그래프 불필요) |
| 5 | 녹음 | 채널별 Dry만, 32f WAV, 채널당 1파일 |
| 6 | 크래시 격리 | in-process (재녹음 가능 전제) |
| 7 | 지연 | 채널 독립, PDC 강제 없음 |

## 5. 기술 스택
JUCE 8.0.11+ / C++17·20 / CMake(`juce_add_gui_app`) / MSVC(VS2022/2026) / ASIO(`JUCE_ASIO=1`) / VST3(`JUCE_PLUGINHOST_VST3=1`) / JSON 세션 파일.

## 6. 개발 단계 (Phase 로드맵)
| Phase | 목표 | 완료 기준 |
|-------|------|-----------|
| 0 | GUI 골격 + 2ch 1:1 패스스루 | 장치 선택, In1/2→Out1/2 저지연 통과 |
| 1 | 채널 VST3 체인 + 네이티브 에디터 | 채널별 wet 출력 |
| 2 | Dry 녹음 (TapProcessor + ThreadedWriter) | sync 맞는 Dry 스템 2파일 |
| 3 | 견고화 (출력 게인·xrun·세션 저장/로드) | 세션 파일로 2채널 재현 |
| 4 | 32채널 확장 + CPU 프로파일링 | 32ch 안정 동작·한계 측정 |

## 7. 미확정 (설계 비차단)
- ASIO 인터페이스 모델 — 채널 수는 런타임 동적 처리, 모델 확인 시 검증 환경 맞춤
- **다중 ASIO 장치 통합 (2026-07-01 검토 → 보류)**: 인터페이스 2대의 ASIO를 동시 선택해 채널 합산 요청. ASIO 호스트 SDK 전역 싱글턴 + JUCE `AudioDeviceManager` 단일 장치 구조라 SW만으론 불가. 근본 문제는 **독립 클럭 드리프트**(워드클럭 미동기 시 샘플 정렬 어긋남 → Dry 동기 파괴). 경로: (A) 워드클럭/ADAT 하드웨어 동기된 다채널 ASIO 사용=코드 변경 0·권장 (B) 집계 드라이버(ASIO4ALL/FlexASIO)=레이턴시↑·동기 미보장 (C) 앱 내 다중 ASIO+마스터클럭+비동기 SRC=대공사. → 결정 보류, 단일 장치 유지.

## 8. 위험 / 완화
| 위험 | 완화 |
|------|------|
| 32채널 CPU 과부하 | 단계적 확장·xrun 측정, 버퍼 상향 |
| 플러그인 크래시(in-process) | 검증된 플러그인 우선, Dry 녹음으로 재처리 가능 |
| 디스크 풀/쓰기 지연 | 락프리 FIFO 오버플로 시 블록 드롭 + xrun, 오디오 무중단 |
| ASIO GPLv3 전염 | 사내/개인용은 무관, 외부 배포 시 재검토 |
